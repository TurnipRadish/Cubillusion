# 幻方 2025-7-24 更新概要

## 使用Python进行代码生成

从这一版本开始，我们使用python进行数据包的代码生成，这样方便做更高级的抽象，也有助于今后进一步稳定地提升开发效率。

所有的python代码都在`python`文件夹中。这里列出一些相关类：

* `Pack`：数据包或资源包的上层抽象。
* `McFunction`：代表数据包的mcfunction文件。
* `CubiEvent`：对Cubi事件的抽象。每个`CubiEvent`的基本定义为若干种注册项的集合。

## 添加事件

目前使用`test2.py`测试所有和事件系统相关的逻辑。你可以在其中编写更多的事件以扩充事件系统。

要新增一个事件类，你需要继承`CubiEvent`，然后选择性地重写相关触发方法。所有触发方法都带有`trigger`前缀，比如触发函数方法`trigger_function`。以下是目前已有的玩家高频事件`PlayerTickEvent`：

```python
class PlayerTickEvent(CubiEvent):
  def __init__(self):
    super().__init__('tick', 'player')
  
  def trigger_advancement(self, adv_trigger = None, condition = None):
    return None  

  def trigger_function(self):
    CubiEventInjector(
      event_class=ServerTickEvent, 
      mcfunction=McFunction(
        f'execute as @a at @s run function {self.get_resource_location()}'
      ),
      inject_tag='#inject - to player tick'
    )
    
    return McFunction(
      'tellraw @s[tag=debug_tick] "ticking"'
    )
```

`trigger_advancement`定义了事件的触发进度，`trigger_function`定义了事件的触发函数。其中，`trigger_function`方法中使用了`CubiEventInjector`来向其他事件注入特定的`mcfunction`片段。这里为了实现玩家高频，利用了服务器高频事件`ServerTickEvent`——在服务器高频事件的触发函数中注入一段`execute`命令，以将其命令上下文的执行者、执行方位分别变更为玩家、玩家坐标系原点。

当然，`ServerTickEvent`中也必须要定义相应的注入标签`#inject - to player tick`：

```python
class ServerTickEvent(CubiEvent):
  def __init__(self):
    super().__init__('tick')
    
  def trigger_advancement(self, adv_trigger = None, condition = None):
    return None
  
  def trigger_function(self):
    self.trigger_func = McFunction(
      '#inject - to player tick'
    )
    super().trigger_function()
    return self.trigger_func
```

为了让`CubiEventInjector`正常工作，必须再调用父类方法`trigger_function`——因为`CubiEvent`的`trigger_function`方法中定义了注入的实现逻辑，如果你不显式调用，则这些逻辑将被忽略。

## 注册事件

所有的事件类都必须有一个相应的实例化对象，以方便注册到相应的事件管理器中。每个事件管理器都应该基于`CubiEventsManager`类：

```python
player_join_world_event = PlayerJoinWorldEvent()
player_tick_event = PlayerTickEvent()

class PlayerEventsManager(CubiEventsManager):
  def __init__(self):
    super().__init__()
    self.register(player_join_world_event)
    self.register(player_tick_event)
```

## 应用注册事件并设置包结构

利用事件管理器，你可以分批地获取各注册项内容，然后基于`Pack`类实现你自己的数据包：

```python
server_events = ServerEventsManager()
player_events = PlayerEventsManager()

class CubiEventPack(Pack):
  def __init__(self):
    super().__init__('TestPack')
    
    self.data = {
      NAMESPACE_EVENT: {
        'advancement': {},
        'function': {}
      },
      VANILLA_NAMESPACE: {
        'tags': {
          'function': {
            'load.json': json.dumps({
              'values': [ f"{NAMESPACE_EVENT}:event_trigger/load" ]
            }, indent=2),
            'tick.json': json.dumps({
              'values': [ f"{NAMESPACE_EVENT}:event_trigger/tick" ]
            }, indent=2)
          }
        }
      }
    }
    
    self.pack_mcmeta['pack']['description'] = 'cubi event dirver'
    
  def add_advancements(self):
    adv = {
      'event_trigger': {
        'player': player_events.get_trigger_advancements()
      }
    }
    adv['event_trigger'].update(server_events.get_trigger_advancements())
    return adv
  
  def add_functions(self):
    func = {
      'event_trigger': {
        'player': player_events.get_trigger_functions()
      }
    }
    func['event_trigger'].update(server_events.get_trigger_functions())
    return func

test_pack = CubiEventPack()
test_pack.gen('./', NAMESPACE_EVENT)
```

`test_pack.gen()`将在运行当前python文件时被调用，其直接控制了数据包的生成行为。

## 已有事件

服务器事件：

* `ServerLoadEvent`：服务器加载事件，由函数标签文件`load.json`实现。
* `ServerTickEvent`：服务器高频事件，由函数标签文件`tick.json`实现。

玩家事件：

* `PlayerJoinWorldEvent`：玩家加入世界后的那一刻要执行的逻辑。
* `PlayerTickEvent`：玩家每刻要执行的逻辑。
